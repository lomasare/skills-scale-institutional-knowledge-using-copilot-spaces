# OctoAcme Project Management Docs

This guide brings together OctoAcme's project management approach, team roles, and delivery processes.

## Project management processes

OctoAcme follows an iterative lifecycle: initiate work by confirming the business need, stakeholders, outcomes, and readiness to proceed; plan approved initiatives into prioritized backlog items, estimates, milestones, dependencies, and a Definition of Done; then execute in small increments, tracking work and risks through the project board and regular reviews. Releases require acceptance criteria, passing CI and security scans, smoke tests, deployment verification, and a rollback or mitigation plan. Retrospectives after sprints, releases, or incidents turn lessons into owned improvement actions.

The Project Manager coordinates delivery, schedules, risks, and communication; the Product Manager defines outcomes, prioritizes work, and measures impact. Developers build and test features, QA validates acceptance and quality, and stakeholders provide input and approvals. Teams coordinate through standups, weekly delivery or PM–Product Manager syncs, milestone demos, and regular stakeholder updates, escalating blockers through the PM, Product Lead, and sponsor as needed. Quality practices include unit and applicable integration tests, end-to-end smoke tests for critical flows, CI tests and linting, security scanning, code review, and manual QA when needed.
